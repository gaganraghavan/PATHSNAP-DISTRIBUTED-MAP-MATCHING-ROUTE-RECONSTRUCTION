# PathSnap

Map matching for the PES University UE24CS352A hackathon: reconstruct the road
route a vehicle drove from its noisy GPS track.

Pipeline: candidate arcs per GPS point → classifier that scores candidates →
HMM/Viterbi decoder over the road network → FastAPI backend + evaluator UI.
The repository currently covers data handling, EDA, candidate generation, feature engineering, the candidate-model
comparison (step 04), Bayesian tuning of the chosen model (05), HMM/Viterbi decoding (06) and route maps (07).
The FastAPI backend and evaluator UI are next.

## Setup

Requires [uv](https://docs.astral.sh/uv/). Python 3.12 is installed by uv if missing.

```bash
uv sync
```

Put the dataset at `dataset/Student folder/` (`train/` and `student_test/`, one
folder per trip), or point `PATHSNAP_DATA` at another folder with the same layout.
The dataset is not committed.

## Reproduce

```bash
uv run python scripts/01_inventory.py          # results/eda/inventory.csv + per-observation labels in artifacts/
uv run python scripts/02_candidate_sweep.py    # results/candidates/{sweep,per_trip}.csv, sweep.png
uv run python scripts/03_feature_engineering.py # candidate features in artifacts/; aggregate summaries in results/features/
uv run python scripts/04_model_comparison.py   # 7 models, 5-fold trip CV + student-test -> results/models/; fitted models in artifacts/models/
uv run python scripts/04_model_comparison.py --feature-set pair   # ablation without context features
uv run python scripts/05_bayesian_optimisation.py --trials 30  # Optuna TPE on LambdaRank -> results/tuning/, models/lambdarank_tuned.*, emission scores in artifacts/scores/
uv run python scripts/06_hmm_decoding.py       # decoder grid on train, classifier-only vs HMM -> results/hmm/, models/hmm_decoder.json
uv run python scripts/07_route_maps.py         # Folium + static route maps for student-test -> results/maps/route_*.html|png
cd notebooks && uv run jupyter nbconvert --to notebook --execute --inplace 01_eda.ipynb
uv run pytest
```

## Key data decisions

- Every trip has its own road network; node and arc ids are local to the trip.
- Coordinates are projected to the UTM zone of each trip's GPS centroid (trips span 25 zones).
- The reference route is a sequence of arcs, not per-point labels. Each GPS point is
  labelled by a monotonic alignment to the route that minimises total distance.
- Candidates: arcs within 100 m, 32 nearest (ties kept). Miss rate on observations
  within 50 m of their label: 0.02 % train, 0.09 % student-test (`results/candidates/sweep.csv`).
- Trips 33 and 54 have most points > 50 m from the reference route; those observations
  are treated as unreliable labels.


## Phase 1 model comparison

`docs/Phase 1 Model Comparison.md` has the protocol, metric definitions, tables and per-model notes.
Seven models (six classifier families plus a LightGBM LambdaRank ranker) are compared with 5-fold
trip-grouped CV on the 80 training trips and then on the 10 student-test trips. The primary metric is
CV mean observation-level top-1 accuracy. LightGBM LambdaRank leads: 0.881 CV top-1 (best in all 5 folds),
0.882 student-test top-1, and the lowest log loss. It is the model taken forward to Bayesian tuning and
the HMM. The step-03 context features (each candidate compared with the observation's other candidates
and with the same arc at neighbouring points) add 7 to 9 points of top-1 for every model; see the ablation in
`results/models/ablation_pair_features/`. Figures are in `results/models/figures/`.


## Phase 2: tuning, HMM decoding and route maps

`docs/Phase 2 Tuning and HMM.md` has the details.

- **Bayesian tuning.** Optuna TPE ran 30 trials on LightGBM LambdaRank, with the same trip-grouped folds as Phase 1 and CV top-1 as the objective.
  - CV top-1 went from 0.8815 (untuned) to 0.8851 (tuned).
  - Student-test top-1 went from 0.8809 to 0.8861, and macro F1 from 0.8421 to 0.8465.
  - The search moved to small trees (8 leaves) with subsampling and L1 regularisation.
  - The search is resumable from `results/tuning/optuna.db`: run step 05 with a larger `--trials` value.
- **HMM and Viterbi.** States are the candidate arcs, emissions are the tuned ranker's probabilities, and transitions use the Newson-Krumm route-vs-GPS distance on the directed road graph. Unreachable moves get a finite penalty, so the decoder survives network breaks. The decoder is tuned on train only, using out-of-fold emissions. On student-test:
  - top-1 went from 0.886 (classifier only) to 0.910, and macro F1 from 0.847 to 0.933;
  - route continuity went from 0.952 to 0.983, and route F1 from 0.928 to 0.983;
  - median route mismatch went from 14.0% to 2.7%.
- **Maps.** `results/maps/index.html` links one interactive map per student-test trip. Each has raw GPS, the road network, the reference route, the classifier-only route and the HMM route, with a legend and layer control.

### Resuming the tuning search on another machine

1. Clone the repo, run `uv sync`, and put the dataset in `dataset/Student folder/`.
2. Run steps 01 and 03.
3. Run `uv run python scripts/05_bayesian_optimisation.py --trials 60`. It loads the 30 trials stored in `results/tuning/optuna.db`, runs the remaining 30, and rewrites the tuned model and the results.
4. Rerun steps 06 and 07 so the HMM and maps use the new model.
